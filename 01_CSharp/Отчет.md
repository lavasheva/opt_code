# Практическая работа 1 Рефакторинг импорта CSV
Вариант 6. Язык C#, .NET 8. Цель - разделить обязанности исходного импортёра и сохранить наблюдаемое поведение.

## Исходная программа
DataImporter читает CSV, разбирает строки, пропускает записи со статусом, отличным от processed, накапливает подходящие записи и имитирует сохранение с задержкой 10 мс. OrderManager выводит число записей. Файл имеет упрощённый формат: значения разделены запятой, экранирование кавычками отсутствует.

## Проблемы и план
Проблема | Техника | Изменение
--- | --- | ---
ImportData объединяет чтение, разбор, фильтрацию и сохранение | Extract Method | Разбор вынесен в CsvParser.Parse
Проверка processed повторяется | Extract Method | Используется IsProcessed
Переменная d не объясняет назначение | Rename Variable | record и column
Proc и Mgr имеют неясные имена | Rename Method | ProcessRecords и ManageRecords
Console и сохранение трудно подменить в тестах | Introduce Parameter | TextWriter и делегат save
Пустой catch скрывает сбои | Introduce State | LastError сохраняет причину
Закомментированный TODO не выполняется | Remove Dead Code | Удалён, экспорт не добавлялся

## Что сохраняется
Имена ImportData, IsProcessed, Proc и Mgr доступны. Старые короткие методы стали обёртками. Порядок вывода, фильтрация, Trim и задержка сохранены. Повторный импорт продолжает накапливать записи: это особенность исходника, а не незаметно исправленная ошибка. Исключение по-прежнему не выходит из ImportData и не добавляет строк в стандартный вывод; причину теперь можно прочитать из LastError.

## Основные изменения
До: внутри LINQ-выражения создавался словарь d, затем в другом месте повторялась проверка статуса. После: CsvParser.Parse возвращает записи, а DataImporter отвечает за сценарий импорта. Сохранение можно подменить простой функцией без настоящей базы. Дополнительные фреймворки и контейнер зависимостей не используются.

```csharp
foreach (var record in CsvParser.Parse(File.ReadAllLines(filePath)))
{
    if (IsProcessed(record)) records.Add(record);
    else output.WriteLine($"Skipping record with status: {record["status"]}");
}
await save(records);
```

## Сложность
Разбор R строк по C столбцам занимает O(R*C), хранение - O(R*C). Сохранение - O(P), где P - число накопленных записей; демонстрационная задержка добавляет около 10*P мс. Ускорение не было целью работы.

При ручном подсчёте исходного ImportData учитываем for внутри проекции, foreach, if и catch: M=1+4=5. В новом ImportData остаются foreach, if и catch: M=4. Цикл разбора перенесён в Parse, а не исчез из программы. Для IsProcessed M=1. Это локальное упрощение метода, не доказательство уменьшения общей сложности программы. Устранён один повтор выражения проверки статуса; массового дублирования в варианте нет.

## Вывод
Метод импорта стал короче по обязанностям, разбор можно читать отдельно, а сохранение - подменять в проверках. Для будущей промышленной версии стоит отдельно согласовать полноценный CSV-парсер, отказ от накопления между импортами и явную политику ошибок: эти изменения затронут исходный контракт.
