Вариант 6 выбран во всех пяти заданиях, где номер определяется последней цифрой студенческого билета. У космического дашборда индивидуального варианта нет.

| Папка | Какая работа | Что внутри |
| --- | --- | --- |
| 01_CSharp | Практическое задание 1, рефакторинг | Импорт CSV, проверки, отчёт |
| 02_CSharp | Практическое задание 2, алгоритмы | Фибоначчи до/после, замеры, график |
| 03_Профилирование_Python | Практическое занятие 3, оптимизация | cProfile, line_profiler, pytest, график |
| 04_Память_Python | Практическое занятие 4, память | tracemalloc, memory_profiler, pytest, график |
| 05_Микросервисы | Практическое задание 3, рефакторинг | Users, Orders, способы оплаты, PostgreSQL, Redis, Postman |
| 06_Космический_дашборд | Практическая работа №4, рефакторинг | Rust, Laravel, PostgreSQL, Python CLI, Compose |

В каждой папке: `Отчет.pdf` для чтения и `Отчет.md` для редактирования, исходники и `Как_объяснить.md` с коротким разбором для защиты. Исходники заданий сохранены в Original.cs.txt и original.py для сравнения. 

## Как запустить

Двойной щелчок по `Запуск.cmd` открывает меню из шести пунктов. Для просмотра кода в VS Code выбрать «Файл → Открыть папку» и открыть папку клонированного репозитория.

C# можно запускать из терминала соответствующей папки:

```powershell
dotnet run -c Release
dotnet run -c Release -- --test
```

Для первого задания автоматическая демонстрация без ожидания клавиши:

```powershell
dotnet run -c Release -- --no-pause
```

Python запускается из папки соответствующей работы:

```powershell
..\.venv\Scripts\python.exe -m pytest -q
..\.venv\Scripts\python.exe ..\benchmark_python.py time
```

В работе по памяти вместо `time` указать `memory`. Два Python-набора запускать из своих папок: в них есть одноимённые модули `original` и `optimized`.

Для повторного создания окружения на другом компьютере, из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для двух Docker-проектов открыть Docker Desktop, дождаться работающего движка и запустить `setup.ps1` из нужной папки. Локальный `.env` создаётся автоматически с новым паролем БД. `.env` не сдавать и не публиковать. Внешние ключи космических API при необходимости вписать самостоятельно в `.env`, ориентируясь на `.env.example`.

В микросервисах после запуска: импортировать `Postman_collection.json` в Postman и выполнить всю коллекцию через Runner. У запросов общий `baseUrl=http://localhost:8000`. Альтернатива из папки проекта: `node smoke.mjs`.

Космический дашборд: `http://localhost:8080/dashboard`. Приёмка и команды тестов находятся в `ACCEPTANCE.md`. Без внешних ключей отдельные API должны возвращать понятную ошибку; успешный ответ платного провайдера без ключа не имитируется.

## Что установлено

VS Code с расширениями Python и C# Dev Kit, .NET SDK 8, Python 3.12, Node.js, Postman, WSL и Docker Desktop. Компоненты Windows Virtual Machine Platform и Windows Subsystem for Linux включены. После включения выполнена перезагрузка; обе контейнерные системы проверены и работают.

Фактические результаты проверок указаны в `ПРОВЕРКА.md`. Есть реальные логи прогонов, интеграционные тесты и скриншоты. Для галереи JWST и Astronomy понадобятся собственные API-ключи; отсутствие ключей обрабатывается сообщением об ошибке. Итоговый репозиторий: https://github.com/lavasheva/opt_code.

## Быстрый показ на защите

1. Открыть `Запуск.cmd`, выбрать работу и показать результат.
2. Открыть её `Отчет.pdf`, таблицу/график и `Как_объяснить.md`.
3. Для микросервисов импортировать коллекцию Postman и запустить Runner; в логах есть уже выполненный прогон.
4. Для дашборда открыть http://localhost:8080/dashboard; ошибку координат можно показать через значение широты 100.
5. Кнопка `Открыть_код.cmd` открывает все проекты в установленном VS Code.

Для переноса на другой компьютер можно выбрать Code → Download ZIP на GitHub. В репозитории нет виртуального окружения, бинарных каталогов и рабочих .env; окружение Python создаётся командами выше, а Docker-образы собираются из исходников.
